One copy of the PSA, Microsoft Graph, CloudRadial and preview/confirm code that every automation needs, pasted into each workflow's PowerShell steps by a small build script.

**Type:** Build source for maintainers (not an automation, and nothing here is imported into a tenant)

## How it works

AutomationAI runs each PowerShell step as one self-contained script, so a step can't import a module. Instead, a workflow `.yml` marks where a library goes, and `inject.js` pastes the library's text between the markers. Edit the library here, run `inject.js`, and every workflow that uses it picks up the change.

| File | What it is |
|---|---|
| `psa.ps1` | One adapter for six PSAs: ConnectWise PSA, Autotask, HaloPSA, Kaseya BMS, Syncro and Zendesk. Same secret names as each PSA's catalog extension. |
| `graph.ps1` | Microsoft Graph: client-credentials sign-in, retries, paging, and the user, group, licence, sign-in and security helpers. A 403 says which permission is missing. |
| `plan.ps1` | The preview/confirm pattern. AutomationAI has no approval step, so a write automation previews its changes and only makes them when the run says `confirm: true`. Used with or without Graph. |
| `cloudradial.ps1` | The CloudRadial API: calls with retry, paging, one Planner card per key (updated, never duplicated), and reports into Report Archives. |
| `inject.js` | Pastes the libraries into an automation's `.yml` files. |
| `tests/` | Strict-mode tests with a mocked Key Vault and mocked web calls. `run.ps1` runs them all. |
| `package.json` | Pins js-yaml for `inject.js` and the inject test. |

## Using a library in a workflow

Put the markers in a step's script, at the indent the script uses:

```yaml
        script: |
          # >>> _shared/plan.ps1 (generated by _shared/inject.js; edit the source, not this block)
          # <<< _shared/plan.ps1
          # >>> _shared/graph.ps1 (generated by _shared/inject.js; edit the source, not this block)
          # <<< _shared/graph.ps1
          $in = Get-NodeInput
          $null = Connect-Graph
          ...
```

Then run, from the repo root:

```
node automationai/_shared/inject.js automationai/<automation-folder>           # fill or refresh every block
node automationai/_shared/inject.js automationai/<automation-folder> --check   # exit 1 if a block is out of date
```

`inject.js` looks at every `.yml` directly in that folder, replaces what's between each start and end marker with the named file from `_shared`, keeps the start marker's indentation, keeps CRLF files as CRLF, and parses the result with js-yaml before writing. A missing end marker or an unknown library stops it with an error and nothing is written.

An automation with its own build (like `new-user-onboarding/src/build.js`) calls it the same way, and its test runs the `--check` form first:

```js
const { execFileSync } = require('child_process');
execFileSync(process.execPath, [path.join(__dirname, '..', '..', '_shared', 'inject.js'), path.join(__dirname, '..'), '--check'], { stdio: 'inherit' });
```

**Never edit the text between the markers in a `.yml`.** It is overwritten on the next run.

js-yaml: run `npm install` in this folder, or set `JS_YAML_PATH` (or `NODE_PATH`) to an existing copy.

## Rules every library follows (and every step that uses one should too)

- **Strict mode.** Steps run under `Set-StrictMode -Version Latest`. Nothing reads a property that might not exist; the `Get-PsaProp`, `Get-GraphProp` and `Get-CrProp` helpers return `$null` instead.
- **State in one hashtable per library**, changed in place: `$PsaState`, `$GraphState`, `$CrState`. The runner runs a step in a child scope where `$script:` variables don't work. Don't create your own variables with these names.
- **Prefixed names.** Every function and helper carries its library's prefix (`Psa`, `Graph`, `Cr`, or `ChangePlan` and `PlannedChange`), so several libraries can sit in one step.
- **Variable names ignore case,** and a function sees its caller's variables. A step variable `$psastate`, or a typed parameter such as `[string[]]$Add` next to a local `$add`, silently clobbers the other one. The tests caught both mistakes while these files were written.
- **Secrets by name only,** from `Get-AzKeyVaultSecret -VaultName $env:RUNNER_KV_NAME -Name <name> -AsPlainText`.
- Lists come back as arrays; wrap a call in `@(...)` so one result is still a list.

## psa.ps1

Connect once, then call the functions. `Connect-Psa` with no argument uses `Get-PsaType`.

| Function | What it does |
|---|---|
| `Get-PsaType [-Requested <string>]` | Which PSA: the run's `psa` input, then the `PSA-Type` secret, then ConnectWise when `CW-ApiUrl` is set. Accepts aliases such as `cw`, `halo`, `kaseya`, `zendesk-ticketing`. Returns `''` when nothing is set up. |
| `Connect-Psa [-Psa <string>]` | Reads the PSA's secrets, signs in (HaloPSA and Kaseya BMS mint a token) and returns `@{ Psa; Base; Headers }`. Names any missing secrets. |
| `Invoke-Psa -Method <string> -Path <string> [-Body <object>] [-ContentType <string>]` | One call. Retries 429 (and GET 502/503/504) honoring Retry-After. Errors read `"<PSA> <METHOD> <path> failed (HTTP n): <reason>"`. |
| `Get-PsaTicket -Id <string>` | `@{ id; summary; description; companyId; status; assigneeId; assigneeIds; raw }` |
| `New-PsaTicket -CompanyId <string> -Summary <string> [-Description <string>] [-Priority critical\|high\|medium\|low] [-Queue <string>] [-Extra <hashtable>]` | Creates a ticket and returns `@{ id; raw }`. `-Queue` is the board (ConnectWise), queue (Autotask, Kaseya BMS), team (HaloPSA), issue type (Syncro) or group id (Zendesk). `-Extra` adds raw PSA fields for tenant-specific required ids. |
| `Add-PsaNote -Id <string> -Text <string> [-Title <string>] [-Public]` | Internal (technician-only) note by default; `-Public` makes it client-visible. |
| `Set-PsaAssignee -Id <string> -UserId <string> [-RoleId <string>]` | Assigns the ticket. Autotask also needs the role id. |
| `Set-PsaStatus -Id <string> [-State closed\|open] [-StatusName <string>]` | Closes (default) or reopens, and returns the status it set. `-StatusName` picks an exact status (an id for HaloPSA and Kaseya BMS). |
| `Find-PsaCompany -Name <string>` | `@(@{ id; name; exact; raw })`, exact name matches first. |
| `Get-PsaOpenCount -UserId <string>` | Open tickets assigned to the technician, or `$null` when the PSA can't count (Kaseya BMS). |
| `Get-PsaLastAssigned -UserId <string>` | Date of the newest ticket assigned to them, `[datetime]::MinValue` for none, or `$null` when the PSA can't tell (Kaseya BMS). |

**Secrets:** the extension's own names (`CW-*`, `Autotask-*`, `Halo-*`, `KaseyaBMS-*`, `Syncro-*`, `Zendesk-*`) plus `PSA-Type`. Optional tenant ids: `Autotask-NotePublishId`, `Autotask-NotePublicPublishId`, `Autotask-NoteTypeId`, `Autotask-NewStatusId`, `Autotask-BillingCodeId`, `Halo-NoteOutcomeId`, `Halo-PublicNoteOutcomeId`, `Halo-ClosedStatusId`, `Halo-OpenStatusId`, `KaseyaBMS-NoteTypeId` (needed for notes), `KaseyaBMS-NewStatusId`, `KaseyaBMS-TicketTypeId`, `KaseyaBMS-TicketSourceId`, `KaseyaBMS-PriorityId`, `KaseyaBMS-QueueId`, `KaseyaBMS-ClosedStatusId`, `KaseyaBMS-OpenStatusId`.

### Calls not yet proven live

Each of these has a one-line `Unverified` comment in `psa.ps1`. Check it against a real tenant before the first live write, then update `reference/build-kit/PSA.md`.

- **Every PSA:** `New-PsaTicket`, `Set-PsaStatus` and `Find-PsaCompany` aren't in PSA.md yet. The exception is Autotask create-ticket and company search, which follow the extension descriptors (`at_create_ticket`, `at_query_companies`).
- **ConnectWise:** create body (`initialDescription`, `board`, priority from `/service/priorities`), closing through the board's `closedStatus` statuses, public notes on the Discussion tab.
- **Autotask:** which `publish` label makes a note client-visible; the `queryCount` field name.
- **HaloPSA:** note `outcome_id` 7 and out-of-box ids (priority 1 to 4, status 9 Closed and 1 New); the `team` field on create; `/Client?search=` reply shape.
- **Kaseya BMS:** the sign-in `GrantType` value `password`; required ids on create; the `/crm/accounts` filter name; status ids; how to list note types.
- **Syncro:** create body (`comments_attributes`, priority labels such as `1 High`); the `Resolved` and `New` status labels; `/customers?query=`.
- **Zendesk:** whether `Zendesk-BaseUrl` already ends in `/api/v2`; organization autocomplete.

## graph.ps1

| Function | What it does | Graph application permission |
|---|---|---|
| `Connect-Graph [-TenantId] [-ClientId] [-ClientSecret]` | Client-credentials sign-in. With no parameters it reads `M365-TenantId` / `M365-TenantID` / `Entra-TenantID` / `Graph-TenantId`, `M365-ClientId` / `M365-ClientID` / `Entra-ClientID` / `Graph-ClientId` and `M365-ClientSecret` / `Entra-ClientSecret` / `Graph-ClientSecret`. Returns `@{ TenantId }`. | |
| `Invoke-Graph [-Method] <string> [-Path] <string> [[-Body] <object>] [-Permission <string>] [-Headers <hashtable>]` | One call. Retries 429, 503 and 504 honoring Retry-After, gets a new token once on 401, and on 403 throws a message naming `-Permission`. `$GraphState.LastStatus` holds the last status. A path without `/v1.0` or `/beta` gets `/v1.0`. | the one you name |
| `Get-GraphAll -Path <string> [-Permission <string>] [-MaxPages <int>]` | Every item, following `@odata.nextLink`. | the one you name |
| `Get-GraphUser -Id <string> [-Select <string>]` | A user by id or UPN, or `$null`. | User.Read.All |
| `Add-GraphGroupMember -GroupId <string> -UserId <string>` | Returns `added` or `already-member`. | GroupMember.ReadWrite.All |
| `Remove-GraphGroupMember -GroupId <string> -UserId <string>` | Returns `removed` or `not-member`. | GroupMember.ReadWrite.All |
| `Set-GraphManager -UserId <string> -ManagerId <string>` | Sets the manager. | User.ReadWrite.All |
| `Revoke-GraphSessions -UserId <string>` | Signs the user out everywhere. | User.RevokeSessions.All (or User.ReadWrite.All) |
| `Set-GraphAccountEnabled -UserId <string> -Enabled <bool>` | Blocks or allows sign-in. | User.EnableDisableAccount.All (or User.ReadWrite.All) |
| `Set-GraphLicense -UserId <string> [-Add <string[]>] [-Remove <string[]>]` | Adds and removes licences by SKU id. The user needs a usage location first. | LicenseAssignment.ReadWrite.All (or User.ReadWrite.All) |
| `Get-GraphSignInActivity [-UserId <string>]` | `signInActivity` for one user or every user. Needs Entra ID P1. | AuditLog.Read.All, with User.Read.All |
| `Get-GraphAuthMethods -UserId <string>` | The user's sign-in methods (`id`, `@odata.type`). | UserAuthenticationMethod.Read.All |
| `Remove-GraphAuthMethod -UserId <string> [-Method <object>] [-MethodId <string>] [-MethodType <string>]` | Removes one method (not the password). | UserAuthenticationMethod.ReadWrite.All |
| `Get-GraphRiskyUsers [-UserId <string>] [-AtRiskOnly]` | Identity Protection risky users. Needs Entra ID P2. | IdentityRiskyUser.Read.All |
| `New-GraphTempPassword [-Length <int>]` | A random password with every character class and no look-alike characters. | |

## plan.ps1

```powershell
$plan = New-ChangePlan "Offboard $upn"
Add-PlannedChange $plan 'Block sign-in' { param($id) Set-GraphAccountEnabled $id $false } -Arguments @($userId)
foreach ($g in $groups) { Add-PlannedChange $plan "Remove from $($g.name)" { param($gid, $id) Remove-GraphGroupMember $gid $id } -Arguments @($g.id, $userId) }
$result = Invoke-ChangePlan $plan -Confirm:$confirm
Set-NodeOutput $result
```

| Function | What it does |
|---|---|
| `New-ChangePlan [-Title <string>]` | An empty plan. |
| `Add-PlannedChange -Plan <plan> -Description <string> -Action <scriptblock> [-Arguments <object[]>]` | Adds one change. Pass loop values through `-Arguments`: a scriptblock reads variables when it runs, not when it was added. Don't use `.GetNewClosure()`, because a closure can't see functions defined in the step. |
| `Invoke-ChangePlan -Plan <plan> [-Confirm <bool or "true"/"yes">]` | Without confirm, nothing runs and the result is a preview. With confirm, the changes run in order and stop at the first failure. Returns `@{ status (preview, done, failed, empty); confirmed; title; message; planned; ran (@{ description; output }); notRun; failed (@{ description; error }) }`. `message` is a plain sentence for a ticket note. |

## cloudradial.ps1

| Function | What it does |
|---|---|
| `Connect-Cr [-BaseUrl] [-PublicKey] [-PrivateKey]` | Reads `CloudRadial-BaseUrl`, `CloudRadial-PublicKey` and `CloudRadial-PrivateKey`. Returns `@{ Base }`. |
| `Invoke-CrApi -Path <string> [-Method <string>] [-Body <object>] [-ContentType <string>]` | One call. Retries 429, GET 5xx and dropped connections, honoring Retry-After. |
| `Get-CrAll -Path <string> [-PageSize <int>] [-MaxPages <int>]` | Every row of a `/v2/odata` list, paged with `$top`/`$skip` (those lists stop at 200 rows with no nextLink). |
| `Get-CrBetaAll -Path <string> [-Take <int>] [-MaxPages <int>]` | Every row of a legacy `/api/beta` list, paged with `Skip`/`Take`. |
| `Set-CrPlannerCard -CompanyId <int> -Subject <string> [-Fields <hashtable>] [-Key <string>] [-Existing <cards>] [-Preview]` | Updates the company's card with that subject (or whose body holds `-Key`), or creates one. Retries without `notes` and the roadmap fields when an older portal refuses them. Returns `@{ action (created, updated, would-create, would-update); productId; optionalFieldsDropped }`. |
| `Get-CrArchive -CompanyId <int> -Name <string> [-Create] [-Category <string>]` | Finds (or creates) a company's report archive by name. Returns `@{ id; companyId; name; inboundAddress }` or `$null`. |
| `Add-CrArchiveReport -CompanyId <int> -ArchiveName <string> -Subject <string> -Html <string> [-Category <string>] [-IsError] [-Preview]` | Writes an HTML report into the company's Report Archive (Compliance > Reports, admins only), replacing an item with the same subject. Returns `@{ action; archiveId; itemId; location }`. |

Reports always go to Report Archives, never to a knowledge base article (client users can see articles), and never hold another client's data. If the archive write fails, keep the report in the run output.

## Tests

```
pwsh -NoProfile -File automationai/_shared/tests/run.ps1
```

Each library runs the way the runner runs it: pasted into one script with the test body, run through `& ([scriptblock]::Create(...))` under `Set-StrictMode -Version Latest`, with `Get-AzKeyVaultSecret`, `Invoke-RestMethod` and `Start-Sleep` mocked. The tests cover each PSA's sign-in, internal and public notes, create-ticket request, close and company lookup; Graph's 429 and 503 retries, paging, 401 refresh and the 403 permission message for every helper; plan preview, confirm and mid-plan failure; CloudRadial paging, card update-or-create and archive writes; and `inject.js` itself.
