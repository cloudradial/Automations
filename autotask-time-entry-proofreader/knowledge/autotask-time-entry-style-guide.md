# Autotask Time Entry Style Guide

Owner: Service Desk Manager · Effective: 2026-11-16 · Used by: Autotask Time Entry Proofreader

> **Example, replace with your own.** The Time Entry Proofreader edits Summary Notes using only the rules in this document. Change the rules to match your own standards. Keep one rule per section, so the right section is found when the agent searches.

## What may be edited?

Only **Summary Notes**. Never change hours worked, date worked, start or end time, resource, billing code, role, contract, ticket, task, or the billable flag. Never edit Internal Notes. Never approve, deny or post a time entry. Skip entries already approved or posted to billing.

## How should a note read?

1. Correct spelling, grammar, punctuation and capitalization.
2. Write complete sentences in the past tense, in a professional tone. "fixed printer" becomes "Resolved the printer connectivity issue."
3. Remove first-person filler and blame. "user broke it again" becomes "Resolved a recurring configuration issue."

## Which shorthand gets expanded?

| Shorthand | Becomes |
|---|---|
| w/ | with |
| w/o | without |
| b/c | because |
| pw, pwd | password |
| usr | user |
| acct | account |
| cx, cust | client |
| tix | ticket |
| mtg | meeting |

Keep standard acronyms such as VM, MFA, DNS and VPN.

## Which product names are standard?

Microsoft 365 (not O365 or office365), Microsoft Teams, Outlook, OneDrive, SharePoint, Windows 11.

## What must never change?

IP addresses, hostnames, device names, serial numbers, usernames, email addresses, file paths, error codes, KB numbers, ticket numbers and version numbers: copy them exactly. Never change technical meaning, and never add or remove work steps.

## What happens to credentials?

Replace any password, secret, API key or MFA code with "[credential removed]", apply the other corrections, and flag the entry with the reason "Credential removed".

## When is an entry flagged instead of edited?

Profanity, frustration or negative comments about the client or users; internal-only remarks (pricing, other clients, internal process); unclear meaning; or a correction that would change technical meaning.

## Are there billing rules?

None in this example. Add rules here (for example "Travel time is non-billable") and the agent flags notes that conflict with an entry's billable status. It never changes the billable status or billing code.

## How long can a corrected note be?

Within 25% of the original length, unless expanding shorthand needs more. Don't pad.

## Examples

- "pw reset for usr, unlocked acct in AD and tested login w/ cx" becomes "Reset the user's password, unlocked the account in Active Directory, and tested the login with the client."
- "o365 mailbox full, archived old emails, user ok now" becomes "Resolved a full Microsoft 365 mailbox by archiving older email. Confirmed the user is working normally."
